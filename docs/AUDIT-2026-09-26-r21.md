# Relay: fourth audit, stress test and fixes (R-21), 2026-09-26

**Scope.** The prototype on `claude/relay-artifact-audit-ngwiqv` (PR #1, head `b76e5e9`, not merged), read as
an adversary: every guard re-proved by planting a violation, every figure recomputed from `data/`, every
engine pushed to its edges, a 1,000-client stress run, and every screen and the walkthrough mockup driven
in Chromium at 1440, 1280 and 1024 px. No doc, test name or PR text was taken on trust.

**Result.** 51 findings: 0 blockers, 14 major, 37 minor. Every major and every minor but one is fixed, each
with a test or a browser check that failed before the fix and passes after. One minor (D-3) and one known
limitation are left open, with the reason, in §2.

**How to reproduce everything here:** `npm run check`, `npx next build`, `npm run e2e` (needs the build),
`npm run stress`. The before-fix evidence is in §5.

---

## 3. Readiness for a live model

**Where a Claude API call would enter, and only there:**

1. **`lib/drafting/compose.ts`**, the client note. Input: the accepted candidate, the household's own figures,
   the cited passages, the resolved note length. Output: text only. It must then pass the unchanged
   `runChecks()` (no projection, every figure sourced, a citation, the disclosure, the call-first rule), and a
   failing draft goes back to the template composer, never to supervision.
2. **Evidence summary** on `/evidence/[oppId]`: a model may summarise the passages `retrieve()` returned. It may
   not decide refusal: `retrieve()` does, before any model is called.
3. **Talking points and the reminder, intro and reply drafts** (`lib/onboarding`, `lib/prospecting`,
   `lib/servicing` draft strings), under the same checks as the note.

**What must stay deterministic** (and is enforced: `deterministic-no-model` and its transitive twin):
eligibility and amounts (`lib/constraints`, `lib/household-math`), ranking (`lib/ranking`), the recipient count
and regime (`lib/recipients`), the policy checks (`lib/policy`), evidence refusal (`lib/evidence`), the
money-movement callback and routing (`lib/servicing`), paperwork escalation (`lib/onboarding`), settings
resolution and the learning guard (`lib/profile`, `lib/learning`).

**What has to change first:** the model call is the one permitted egress. Today `no-outbound-transport` and the
CSP block every other host. Put the SDK in one server-only module (for example `lib/model/`), add a single
dependency-cruiser exception for it, keep the browser CSP at `'self'` (the call runs on the server), send only
the grounding bundle from `getClientFile()` with names reduced to initials, record the model and prompt version
beside the settings version on the rationale record, and add a golden set before any client-facing use
(PRD §8.3).
